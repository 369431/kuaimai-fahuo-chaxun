# 打包与发版（打安装包 → 发升级）

面向维护者。**只打包装不碰业务逻辑**，全部配置已入库在 `packaging/`。

## 一、一键打安装包

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File packaging\build.ps1
```

它按顺序做四件事，全用脚本自身位置推路径（换电脑 / 换目录都不用改）：

```
[0] 版本号：没传 -Version 就从 desktop\kuaimai_client.py 的 APP_VER 读
[1] 找 ISCC.exe（Inno Setup 6）：%LOCALAPPDATA%\Programs\Inno Setup 6\ 或 Program Files
[2] packaging\assets\*  →  packaging\staging\
[3] https\ 的转发脚本 → staging\kuaimai_https\（km_https.py / certinfo.py / static / 证书空目录）
[4] staging\frp\frpc.exe（本地没有则调 download_frp.ps1 抓）
[5] PyInstaller 打主程序 → staging\快麦扫码查询.exe
[6] ISCC 出安装包 → packaging\out\快麦扫码查询_安装版_v<版本>.exe
```

常用开关：`-Version 1.26` 显式指定版本；`-SkipPack` 复用上次的 exe 只重摆 staging；`-SkipFrp` 不抓 frpc。

**前置**：Python + PyInstaller、Inno Setup 6。（frpc.exe 是第三方二进制，不入库，首次跑自动下载。）

## 二、推给客户端（让别的电脑「检查更新」能看到）

```powershell
python tools\_do_release_v125.py        # 照这个改一个 v1.26 的副本
```

`release.py` 会：把安装包复制成 ASCII 名 `kuaimai-scan-setup-v<版本>.exe` → 算 sha256 →
`gh release create`（已存在则 `--clobber` 覆盖）→ 写 `version.json`（version/notes/setup_url/sha256/**size**）→ 提交推送。

### ⚠️ 推完必须清 jsDelivr 缓存

客户端默认清单源是 **jsDelivr**（`cdn.jsdelivr.net/gh/...@main/version.json`），raw 只是备用。
不清缓存时 GitHub 上已是新版、**jsDelivr 仍返回旧版** → 别的电脑点检查更新会以为「已是最新」。

```
https://purge.jsdelivr.net/gh/369431/kuaimai-fahuo-chaxun@main/version.json
```

响应 `status: finished` 后约 5 秒生效。**每次发版都要做，忘了这一步等于白发。**

## 三、发完怎么验

1. **安装包元数据**：`(Get-Item packaging\out\快麦扫码查询_安装版_v1.25.exe).VersionInfo.ProductVersion` 要对上版本号。
2. **包内代码是新版**（单文件把 pyc 压缩进 PKG，二进制搜字符串搜不到，必须解包）：
   用 `PyInstaller.archive.readers.CArchiveReader` 取 `PYZ.pyz` → `ZlibArchiveReader` → `extract('kuaimai_client')`
   → `marshal.loads` → 遍历 `co_consts` 找标记串（`v1.25`；`kuaimai_print` 里找 `speed_print_btn` 等）。
   参考 `tools\_check_pack_v124.py`。
3. **两个源都已是新版**：jsDelivr 与 `raw.githubusercontent.com/.../version.json` 都读一遍 version。
4. **端到端**：`import kuaimai_update` 跑 `check("v1.24")`（要 has_update）+ `download_setup()`（sha256 应自动通过）。

## 四、踩过的坑（别重复）

- **`.ps1` 必须带 UTF-8 BOM**：没有 BOM 时 PowerShell 5.1 按 GBK 读，中文注释/字符串直接把脚本解析成语法错
  （报 `Unexpected token` 一堆）。本目录两个 .ps1 都是带 BOM 的，改完记得确认 BOM 还在。
- **PS 5.1 里别用 Python 风格格式化**：`"…{0}…" % $x` 会报 `Cannot convert value … to type System.Int32`，要用 `-f`。
- **原生命令写 stderr 会被当致命错误**：`$ErrorActionPreference='Stop'` 下跑 `python` / `ISCC` / `frpc --version`，
  它们往 stderr 写 INFO/版本行时 PS 会造 `NativeCommandError` 直接终止（看着像构建失败，其实只是日志）。
  调原生命令前把 `$ErrorActionPreference` 临时降成 `Continue`，只认 `$LASTEXITCODE`。
- **`release.py` 写 version.json 时要带上 `size`**：原先只写 sha256，size 会一直是上一次的陈旧值
  （v1.24 清单写 28234889、真实 28447760）。客户端只校验 sha256 所以此前无害，但字段是错的。
- **别用 README 那条裸 `--onefile` 命令打正式包**：它没带 `hiddenimports`，打出来的 exe 点「打单」会
  `ModuleNotFoundError`。spec 里必须带上 `kuaimai_print` / `kuaimai_print_ui` / `kuaimai_print_jobs` /
  `auto_print_watcher`（这几个只在运行时 import，静态分析扫不到）。
- **`km_https.exe` 必须放在 `kuaimai_https\` 里**：它的 `BASE` 取 `sys.executable` 所在目录，
  `static\` 与 `lego\certificates\` 都在 exe 旁边找。它不打 datas，静态资源靠目录摆。
- **打包用 Python 解释器跑、别让控制台代码页经手中文路径**：调 ISCC 时用 `subprocess.run([iscc, iss, "/D…"])`
  这样列表传参，中文路径与 `-D` 定义都安全。
