# 快麦扫码查询 · 打单对接说明（ERP 网页版）

> 记录于 2026-09-21 实测抓包。目标：在「快麦扫码查询」里从**扫码日志选行** → 自动在 ERP 打单页勾选 → 取号 → 打印 → 回写。

## 一、环境

| 项 | 值 |
|---|---|
| 打单页 | `https://erpb.superboss.cc/index.html#/trade/printv2`（快麦ERP--订单打印V2） |
| 浏览器 | Edge（独立配置目录 `%LOCALAPPDATA%\KuaimaiScan\edge-automation`，登录态存这里） |
| 调试口 | CDP `http://127.0.0.1:9222`（`--remote-debugging-port=9222`，需 `suppress_origin=True`） |
| 要点 | 页面工具条上的按钮可能**不吃 `element.click()`**（取号类实测 0 请求），且按钮上方可能有隐形浮层；能用 JS/fetch 的**一律走接口**，别点按钮。必须点按钮时走**真实鼠标点击**（见 四点七） |
| 打印机 | HPRT N31（USB002，默认）；面单尺寸 **76×130mm** |

## 二、实测接口（都在页面内 `fetch` 调用，自动带登录态）

### 1) 取号
```
POST /pt/waybill/code/get
入参: sids=6029578498234808[,6029578498234809]&api_name=pt_waybill_code_get
返回: data.successList[] = {sid, outSid(运单号), logisticsCompanyName(快递公司),
                            logisticsCompanyId, templateId, expressId}
      data.failList[]    = {sid, message}   # 例:「订单已有快递单号」
      data.expressForwardFailList[]
```
> 未取号的订单会在这里**真的向快递取号**（不可撤回），批量注意。

### 2) 打印前校验 / 打印相关（实测链路，按顺序发起）
```
POST /pt/waybill/valid/have/multi/tag      body(JSON): {"sids":"...","api_name":"pt_waybill_valid_have_multi_tag"}
POST /pt/printing/status/query/sids        入参: sids=...&api_name=pt_printing_status_query_sids
POST /pt/waybill/valid/before/print        入参: sids=...&entrance=4009&multiTemplate=1&operateType=0
                                                &isNeedWaybill=0&filterRepeat=1&needCheckAll=1
                                                &isSpecifyPrinter=1&api_name=pt_waybill_valid_before_print
GET  /pt/logistics/company/getPrinterName?sid=...&api_name=pt_logistics_company_getPrinterName
```
> `valid/before/print` 的返回若提示「订单未获取运单号」，就是取号没做（ERP 会拦）。
> 打印机由「多平台打印设置」按**快递公司**自动选定（中通/申通各自绑了打印机）。

## 三、打单业务规则（用户口径，必须遵守）

1. **优先级：加急单优先**；其次**剩余时间少的先打**；`剩余时间` 为**负数更要优先**（超时最急）。
   - 页面行里字段 `trade-remainTime`，形如 `48.0小时`，负数也在同一格。
   - 加急口径与现货可发页一致：**中通/申通 加急订单数**。
2. **只打「一单一件」的订单**：
   - 一单一件 = 该订单**只有一个非赠品的商品编码**（数量 1）。
   - 例：`7107-黑色M` ✅；`7107-黑色M, 1166` ✅（**1166 是赠品，不计**）。
   - 一单多件（例：`7107-黑色M, 7107-白色M`）❌ **不能勾选、不能打印**。
3. 口径与「快麦查询」现有算法**保持一致**（复用下面的函数，别另写一套）。
3.1 **只打网页扫到的那个编码**：当次提交的 `商家编码` 是什么，就只打「一单一件且非赠品编码 **等于** 该编码」的订单；**不同编码的单一律不打**（跳过并给出原因「编码不符(实际编码)」）。
4. **一次最多 500 单**（快麦限制）：整体按 500 封顶；**取号分批调用**（每批 ≤20 个 sids 更稳）。
5. **打印后不自动标「已打」**：必须人工确认真的出单了，由人工标记。程序只负责打印 + 展示结果（运单号/快递公司/成功失败），不写「已打」。

## 四点五、已跑通的打单流程（2026-09-21 实测出纸 3 张）

```
1) 实时查单（按扫到的编码）
   POST /trade/search
     api_name=trade_search&queryId=77（快递单未打印）&pageSize=300
     &field=timeoutActionTime        ← 关键：用 pay_time 会把最急的单漏在页外
     &needOrder=1&useCompress=0&outerId=<商家编码>
   → data.list[]：sid/tid/shortId/itemCount/printCount/expressName/timeoutActionTime
     以及 orders[]（明细：outerId、num、giftNum、platformGift）
2) 剩余时间 = timeoutActionTime/1000 − now（负数=超时；promiseDeliveryTime 等是占位值）
3) 挑单（kuaimai_print.pick_orders）：编码匹配 + 一单一件 + 加急优先 + 剩余时间升序，≤500
4) 取号：POST /pt/waybill/code/get  body: sids=...&api_name=pt_waybill_code_get（分批 ≤20）
5) 勾选 + 打印（打单页）：
   - 用 URL 参数筛单（不靠填输入框）：
     #/trade/printv2/?queryId=77&module=printv2&warehouseId=556677&order=asc&pageNo=1
       &pageSize=300&timeType=pay_time&expressStatus=0&orderIdTypeSelect=mixKey
       &key=mainOuterId&queryType=1&skuOuterId=<商家编码>
   - 按 **短号(shortId)** 匹配行 → 点行内 input[type=checkbox]
   - **保险：勾到的行数不等于预期，绝不点打印**
   - 点工具条 **「多平台打印快递单」**（`data-name=print_express_plus`）→ 详见 **四点七**
     - ✗ 旧名「多平台极速打印」（`data-name=speed_print_btn`）**已不再渲染**，按旧名找会 `not-found`
     - 点完先弹【打印设置】弹窗，确认按钮是 **「打 印」（中间带空格）且是 `<a>`** → 必须去空格匹配（见 四点七 / 踩坑 7）
6) 打印后**不自动标「已打」**（人工确认出纸后自己标）
```

**踩过的坑（别再犯）**

1. `field` 必须用 **`timeoutActionTime`**；用 `pay_time` 只取回最早 20 单，**会把最急的单漏掉**。
2. 商家编码过滤参数：**`outerId`**（服务端）/ **`skuOuterId`**（页面查询栏）；`sysOuterId/mainOuterId/platOuterId/code` 都不过滤。
3. 工具条按钮（尤其取号）**不吃 `element.click()`**（实测 0 请求）；打印按钮改用**真实鼠标点击优先**（CDP，见 四点七），JS click 仅兜底；点击位置可能被隐形浮层挡住（清场方式见 四点六：**不要** `Page.bringToFront`）。
4. 全页 `input[type=checkbox]:checked` **会算上筛选下拉框的选项**（`li.el-cascader-node`），判勾选必须限定在订单行容器 `div.module-list-item-inpage` 内。
5. 响应很大（300 单约 58 万字符），CDP 取值要**大切片**，否则 JSON 截断解析失败。
6. 选单脚本必须带「勾到才点打印」保险，失败不要反复点。
7. **确认按钮是「打 印」（中间带空格）且是 `<a>` 不是 `<button>`** ✗：点「多平台打印快递单」会先弹【打印设置】弹窗，按 `'打印'` 严格匹配 `button` **点不到** → 表现就是「按钮点到了但确认不了 → 不出纸」✗。匹配前必须 `replace(/\s+/g,'')` 去空格，且选择器要含 `a,.ui-dialog-btn` ✓。
8. **别用「真实鼠标点击 + JS 点击」双保险**：两次点击会触发**重复打印** ✗。正确做法是真实鼠标点击后监听事件是否落到目标控件（`data-km-printbtn`），**只有没落到**才回退 `element.click()` ✓。

**已验证可用**：`tools/erp_probe.py`、`tools/erp_api.py`、`tools/erp_watch_net.py`、`desktop/kuaimai_print.py`（`selftest` 全过）。

> ⚠️ `tools/erp_print.py` / `erp_print_run.py` / `erp_print_run2.py` 仍按**旧按钮名**「多平台极速打印」查找点击 → **现已失效** ✗，只作历史/探针参考；打单实现见 `desktop/kuaimai_print.py`（四点七）。

## 四点六、打单上线后的最终形态（2026-09-22 实测定稿）

1. **打单浏览器必须「最小化窗口」启动**（专用配置目录）：
   `--remote-debugging-port=9222 --user-data-dir=%LOCALAPPDATA%\KuaimaiScan\edge-automation --start-minimized <打单页URL>`
   - ❌ **不要用 `--headless=new`**：实测打印组件（C-Lodop）拿不到指令 → **不出纸**
   - ❌ **不要调 `Page.bringToFront`**：会把浏览器弹到前台（要求全程后台静默）；页面内 JS 点击即可完成勾选/打印
2. **登录检测**：`ensure_browser()`（缓存 5 分钟）→ ok / need_login / no_browser；已登录则全程静默，未登录只提示一次
3. **查询量**：单次上限 500；也可按需要量缩小（want×3，最少 60）；缓存：加急 sid 60s、查单 120s、浏览器自检 300s
4. **后台预取**：每 45 秒预取扫码记录里待打编码的订单（每轮最多 5 个）→ 点打单秒开
5. **判重**：`打印次数 > 0` 才跳过（**预发货有单号但未打印的照打**）；「已打」由人工点那格标记，不自动标
6. **界面交互**：扫码记录「可打单数量」那一格 = 打单入口（点数字 → 弹「是否直接打印」→ 是才打）；**双击整行不再切「已打」**；已打列格显示「【打单】」
7. **打印 ≠ 发货**：出纸后订单仍是「待发货」，要另点「发货」（上传单号/出库）后才变「已发货」；物流状态显示「待发货」直到快递揽收

## 四点七、按钮定位与点击（2026-09-22 实测定稿）

**现状**：工具条**已不再渲染**「多平台极速打印」（`data-name=speed_print_btn` 已消失 ✗）；现在实际可点的是 **「多平台打印快递单」**（`data-name=print_express_plus` ✓）。

`desktop/kuaimai_print.py` 已实现并**实测真出纸** ✓，顺序如下：

1. **`data-name` 优先**（ERP 自己的标识，改文案也不怕）：`speed_print_btn`(60) > `print_express_plus`(55) > `speed_print_send_right_now`(20)；
2. **文案兜底**：`多平台极速打印`(50) > `多平台打印快递单`(45) > `极速打单发货`(20) > `极速打印`(15) > `打印/批量打印/打印面单`(10)；同分取**面积最小**（命中里层可点元素）；
3. 只认**可见且未禁用**的元素（像素尺寸 / computedStyle / `disabled` / `aria-disabled` / `is-disabled`）；命中后打标记 `data-km-printbtn=1`，后续按标记点击（避免再找一次又变了）；
4. **真实鼠标点击优先**（CDP `Input.dispatchMouseEvent`，页面视口坐标）；先武装监听判断事件**是否真落到标记控件**上 → **仅在真实点击未落到目标时**才回退 `element.click()` → **防重复打印** ✓；
5. 没找到则尝试展开「打印 / 批量打印 / 打印面单」下拉再找一次；最终失败时把**工具条逐项**（文本 + `data-name`）与页面候选控件 dump 进日志（失败自证）。

**确认弹窗（最容易卡住的一步）**：点「多平台打印快递单」后先弹【打印设置】弹窗，确认按钮文案是 **「打 印」（中间带空格！）** 且是 **`<a>` 而不是 `<button>`** ✗ —— 按 `'打印'` 严格匹配 `button` 会点不到，表现为 **「按钮点到了但确认不了 → 不出纸」** ✗。
做法：匹配前 `replace(/\s+/g,'')` 去掉空格 + 选择器放宽到含 `a,.ui-dialog-btn` ✓。

**为什么「极速打单发货」（`data-name=speed_print_send_right_now`）刻意排最后** ✓：它的提示语含「打印后一键直接发货」→ 有**误发货风险** ✗；它只是兜底候选，排序永远靠后，正常路径绝不会命中 ✓。
